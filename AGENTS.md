# Repository instructions

For English essay / composition presentations, read and follow [the essay presentation standard](docs/english-essay-presentations.md) before creating or modifying the deck. It captures Simon's requirements for pedagogy, simple English, interactive paraphrases, fonts, paragraph layout, punctuation, stable scrolling and publication links.

The latest smartphone-age essay presentation is the implementation reference: grade11/smartphone-age-essay/index.html. These instructions apply to similar essay presentations, not unrelated lessons. The user's current explicit instructions take precedence.

## Publication status links

Simon requires every response providing a presentation link or a published website fix to include a link to the deployment status for the exact published commit (GitHub Actions run / Pages build and deployment), alongside the live page URL. A source-code commit link is not a substitute. Verify and report the deployment state honestly: pending, in progress, succeeded, or failed. This rule applies to all work on this repository, across conversations and projects.

## Placement of new class materials

Standing instruction confirmed by Simon on 2026-10-22: when publishing a new presentation or other class material, place its link first in the relevant class section of the main site (`index.html`) and at the top of the relevant class/group page and class materials library wherever those entry points exist. Resolve the correct class and current entry points for each task; preserve existing materials and the site's established card styling.

A link in an internal library alone does not complete publication. For Grade 10, check all three entry points: `index.html` under `#grade10`, `grade10/group-a/index.html`, and `grade10/group-a/library/index.html`.

Before reporting completion, verify the deployment for the exact commit succeeded and check that the live class entry points show the new link in the required position and that its destination opens. If verification is blocked or deployment is pending or failed, state that accurately. Include the live presentation/material URL, the updated class entry URL, and the exact deployment-status URL in the completion response.
